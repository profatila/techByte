A função do ProdutoMemoryRepository

A ProdutoMemoryRepository é a classe que coloca a "mão na massa" para salvar, buscar, atualizar e deletar os produtos de fato, guardando tudo na memória RAM do computador enquanto o programa está rodando.

A diferença prática entre ProdutoRepository e ProdutoMemoryRepository
Para entender a função dela, pense na relação entre um Contrato de Trabalho e o Trabalhador:

ProdutoRepository (Interface / Contrato):
Ela é apenas uma lista de regras sem código nenhum. Ela apenas diz: "Qualquer classe que quiser salvar produtos neste sistema OBRIGATORIAMENTE precisa ter os métodos salvar(), buscarPorId(), atualizar() e deletar()."
Ela não sabe COMO salvar, apenas cobra QUE seja salvo.

ProdutoMemoryRepository (Classe Concreta / Trabalhador):
É a classe que executa as ordens do contrato. Ela pega aquela lista de regras da interface e escreve o código em Java puro de como fazer aquilo na memória do computador.

Qual é a função da ProdutoMemoryRepository?
Ela possui três responsabilidades principais:

Criar a "Gaveta" de Dados:
Ela cria e mantém a lista List<Produto> produtos = new ArrayList<>(). Essa lista funciona como o banco de dados temporário da aplicação.

Gerar IDs Automáticos:
Ela controla a variável proximoId = 1, garantindo que o primeiro produto seja ID 1, o segundo ID 2, e assim por diante.

Executar a Lógica Bruta de Manipulação de Dados:
É ela quem de fato faz o produtos.add(), quem percorre a lista com .stream().filter(), quem remove itens com .removeIf() e altera posições com .set().

Por que separar em duas coisas? (O Grande Ganho do Projeto)
Imagine o seguinte cenário na TechByte Solutions:

Hoje, o protótipo roda em memória RAM via ProdutoMemoryRepository. Mas no mês que vem, a diretoria decide guardar os produtos em um Banco de Dados de verdade (MySQL).

Se não tivéssemos essa separação:
Você teria que reescrever a View, o Controller, ajustar códigos por todo o projeto e corria o risco de quebrar o sistema inteiro.

Com a estrutura atual:

O seu Controller conversa apenas com a interface ProdutoRepository (ele não quer saber se o dado tá na memória RAM, em arquivo texto ou no MySQL).

Para mudar para MySQL, você só precisa criar uma nova classe:


public class ProdutoMySQLRepository implements ProdutoRepository {
    // Aqui vai o código que conecta no MySQL
}


No arquivo Main.java, você altera apenas 1 linha:

// Antes:
ProdutoRepository repository = new ProdutoMemoryRepository();

// Depois:
ProdutoRepository repository = new ProdutoMySQLRepository();

A View e o Controller continuarão funcionando 100% iguais, sem precisar alterar uma única linha de código neles.

A ProdutoMemoryRepository serve exatamente para isso: ser a primeira implementação (em memória) da sua regra de dados, fácil de rodar, testar e substituir no futuro.
